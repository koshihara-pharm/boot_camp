# 薬のワンポイント（うさぎ薬剤師の一言）

「苦い」だけでは、親に刺さらない。**「この薬は、ここに気をつける。なので、これがおすすめ」**を、うさぎ薬剤師が親身に、短く言う。
2026-11-24 に、モビコールの叩きを3回作り直して、ユーザーが「すごく良くなりました」と言った形を、言葉にしたもの。
手本は、このフォルダの `tataki.html`（モビコールの叩き）。
2つ目は、2026-11-26 のワイドシリン細粒（親の声でいちばん多かった「ピンクの粉」。声に、本と病院の表で答えた）。

迷ったときの順番: CLAUDE.md の「守ること」 → CLAUDE.md の「決まったこと」 → docs/22 → このスキル。

## 1. 先に読むもの

- 資料の**原文**。ページの中身が画像なら、画像を見る（モビコールの参考のページは、本文が1枚の表の画像だった）。ハンドブックの写真は、要点を自分の言葉にする（写真はリポジトリに入れない）
- docs/34（嫌がられやすい薬のリスト）と「嫌がられやすい薬の表」の、その薬の欄（嫌がられる理由、資料にあった飲ませ方）
- data.js のその薬（FACTS）と、**そこに書いてあるメモ**。「消した」「出さない」と薬剤師が決めたことが書いてある（例: モビコールは、水の量・温度・保存のコツを 2026-11-11 に消した）
- docs/24 のその薬のカード
- **親の声**（docs/_local/33_sns_komarigoto.md。SNS の困りごとの調べ。GitHub に上げない）。その薬で、親が何に困り、何を試し、何がだめだったかを見る。足りなければ、スキル komarigoto-chousa で調べる（2026-11-26 ユーザーの指示「声をみて」）

## 2. 中身の決まり

1. **型は「気をつけたいこと → おすすめ」**。うさぎ薬剤師の一言は、この2つだけ。それぞれ1〜2文
   - 気をつけたいこと: 嫌がられる理由を、そのまま言う（味、後味、ざらつき、量、におい）。子どものせいにしない
   - おすすめ: いちばん効く1手を言う。細かいことは、下の箱に回す
2. **資料に書いてあることだけ**。資料で言えることと、言えないことを分ける。私の推測は入れない
3. **資料の表や文は写さない**。星や印の数は、言葉に言いかえる（例: 星5つの3つ →「とくに、りんごジュース・スポーツ飲料・乳酸菌飲料は、しょっぱさを感じにくいとされています」）。**「はじめの3つ」「上の3つ」のように、並んだ場所で指さない。名前を書く**（2026-11-26 ユーザー「上の3つがわかりにくい」。札は、画面の幅で折り返すので、どれが3つ目かが分からない）。「参考にした資料」に、資料の名前と日付を足す
4. **前に薬剤師が消した中身にふれるときは、勝手に戻さない**。叩きに入れてもよいが、返事の「薬剤師として決めてほしいこと」に必ず出す
5. **医療上の判断は書かない**。飲む量・回数、薬の形を変える、ほかの薬との飲み合わせは、医師・薬剤師に聞く導線にする。相談の案内は折りたたまない
6. 今のサイトと変わる所（○ が ◎ になる、× が増える、など）は、変わる前と後を並べて見せる
7. 言葉は、docs/22 の「使う言葉の一覧」に合わせる。新しい言葉（例: 「しょっぱさ」）を使ったら、一覧に足すかをユーザーに聞く
8. **親の声は、「何に答えるか」を決めるために使う**。答えの中身は、資料から書く。声だけを根拠に、食べ物や飲ませ方を足さない。投稿の文は写さない（困りごとを、自分の言葉でまとめる）。資料で答えられなかった声は、返事に「まだ答えられていない声」として書く

## 3. 見た目の決まり（シンプルに。ただし、情報は削らない）

ユーザーの言葉（2026-11-24）: 「情報としてはいいけど、なにかみにくい。シンプルなデザインにしてみやすく。ただ、情報をけずれという意味ではない」

**足すのは、うさぎ薬剤師の一言の箱が1つだけ。あとは、今のサイトの薬の画面と同じ部品だけを使う。**

並べる順（上から）:

| 順 | 部品 | 決まり |
|---|---|---|
| 1 | 薬の名前、薬の味 | 今のまま。オレンジの題は、この1つだけ |
| 2 | **うさぎ薬剤師の一言** | 画面に1つだけ。うすいオレンジの面（枠も影もなし）。上に顔の丸（黄色の輪）と「うさぎ薬剤師から」。中は、小さい見出し「気をつけたいこと」「おすすめ」と、それぞれの文 |
| 3 | ◎ 混ぜると飲みやすい ／ ○ 混ぜても大丈夫 ／ × 混ぜないほうがいい | 今の箱と札。箱の中を分けたいときは、**小さい見出し（字だけ）**で分ける。分け方は、親が選ぶときの言葉にする（「甘いもの」「温かいもの」「固まった食べ物」） |
| 4 | コツ | 今の箇条書き |
| 5 | 相談の案内 | うすい面の箱。折りたたまない |
| 6 | 参考にした資料 | 今の折りたたみ |

**やらないこと**（1回目と2回目の叩きでやって、「見にくい」と言われた）:

- 吹き出しを2つ以上置く（話が散る）
- 目もりの棒、グラフ、星を並べる（目がそこに引っぱられる）。**強さや順位は、言葉で言う**
- 箱の中に、線で区切った箱や、白い箱を入れる
- コツを、絵つきの札にする
- 新しい色や飾りを足す

**情報を削らないための確かめ方**: 形を変えたら、「前の出し方 → 今の出し方」の表を作る。前にあった情報が、今のどこにあるかを1つずつ書く。言い方がゆるくなった所は、正直に書く。

注意書きは、関係する札のすぐ下に置く（例: 「冷ましてから溶かします」は、コツの欄ではなく、「温かいもの」の札の下）。

## 4. 手順

1. **資料を読む**。分かったことを、資料で言えること・言えないことに分ける
2. **今のサイトの中身と比べる**。増えるもの、欄が変わるもの、前に消したものとぶつかるものを洗い出す
3. **叩きを1枚作る**。`tataki.html` を写して、薬の名前・味・一言・箱の中身・資料を入れかえる。まず1つの薬だけ（CLAUDE.md の最上位の考え）
4. **スマホの幅で撮って、自分の目で見る**（下の「撮り方」）。見ないで出さない
5. **ui-check** の観点で見る（3秒テスト、言葉、一貫性、配置、誰でも、流れ）
6. **見せる**。非公開の Artifact に出して、画像も送る
   - Artifact に出すときは、叩きの HTML と、使った絵（`img/usagi_oyako.webp`、`img/fluent/*.svg`、`img/food/*.png`）を `files` で一緒に送る（`root` はリポジトリのいちばん上）
   - 同じ薬を直すときは、同じファイルを出し直す（同じ URL のまま新しくなる）
7. **返事に書くこと**
   - ページの流れ（一言、◎○×、コツ）
   - **薬剤師として決めてほしいこと**を番号で（前に消したもの、欄が変わるもの、新しく × にするもの、数字を出すか）
   - 「親の声 → ページのどこで答えたか」の表（答えられなかった声も書く）
   - 資料のこと（何から取ったか、どう言いかえたか）
   - 形を直したときは、「前の出し方 → 今の出し方」の表
8. **決まったら、サイトに入れる**。docs/24 のその薬のカード → data.js → index.html の順。画面を変える前と後に ui-check。本番に出すのは、ユーザーが「出して」と言ってから。入れたら、「嫌がられやすい薬の表」のその薬を「入れた」にする（Artifact のデータベースの `kime` の `applied` を true に）

サイトへの入れ方（data.js のどの欄に一言を持つか、index.html でどう出すか）は、最初の1つを入れるときに決めて、ここに書き足す。2026-11-24 の時点では、叩きまで。

## 5. 撮り方

Chrome は、窓の幅を 500px より細くできない。そのまま 390px で撮ると、右が切れて写る。このフォルダの道具は、幅 390px の枠の中にページを入れて撮る。

```
node .claude/skills/kusuri-onepoint/toru.cjs <叩きの HTML> <出す PNG> [高さ。なければ 2400]
```

- 叩きの HTML は、Artifact に出す形（`<title>` から始まり、`<html>` や `<body>` を書かない）でよい
- 絵（`img/...`）は、リポジトリのいちばん上から読む
- 撮った画像は、Read で開いて見る

## 気をつけること

- 叩きのファイル（`try_*.html`、`try_*.png`）は、見るためのもの。サイトのファイルではない
- うさぎ薬剤師の言葉は、ていねいで短く。「〜です」「〜ます」。おどかさない
- 後発品は、会社ごとに味がちがう。一般名の行には、1つの会社の味の話を書かない（CLAUDE.md「薬の味の書き方」）
- 資料が1つだけのとき、個人の味見のブログだけのときは、そのことを返事に書く
