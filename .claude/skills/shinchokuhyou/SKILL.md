# 進捗表

元にした考え方は docs/21。
**台帳（進捗ファイル）に残し、毎回の返事で表として見せる。** トークンの節約より、迷子にならないことを優先する。

## 1. 使うかを最初に聞く

作業が3ステップ以上になりそうなとき、手をつける前に1回だけ聞く:
「進捗ファイルと進捗表を使いますか」

- 使う → 2 へ
- 使わない → このスキルはここで終わり。その作業ではもう聞かない
- ユーザーが /shinchokuhyou と打ったときは、聞かずに使う

## 2. 進捗ファイル（台帳）を作る

- 置き場: `.claude/shinchokuhyou/YYYY-MM-DD_作業の名前.txt`（このフォルダは .gitignore に入っていて、GitHub に上げない）
- 前の作業の台帳が残っていたら、続きかどうかをユーザーに聞き、続きならそれを読んでから始める
- 台帳に書くこと（ふつうの文字で。表の形でなくてよい）:

```
# 作業の名前
始めた日: 2026-10-23

## ステップ
1 | 要件を決める | ユーザー | チャット | 済み
2 | 計画ページを作る | Claude | html-plan | いまここ
3 | 計画を読んで決める | ユーザー | 計画ページ | まだ

## 決めたこと
- 2026-10-23 決める欄は2つにしぼる（ユーザー）

## ユーザーの発言（要点）
- 2026-10-23 「スマホで読めるように」
```

- ユーザーの発言は、作業の向きを変えるものだけ要点で書く。本名、子どもや家族のこと、勤め先のことは書かない
- ステップが進んだり、増えたり、決めたことが出たら、返事を書く前に台帳を直す

## 3. 毎回の返事に表を入れる

返事の最後に、台帳から作った表を入れる。**全部のステップを、省かずに入れる。**

| # | ステップ | だれ | どこで | 状態 |
|---|---|---|---|---|
| 1 | 要件を決める | ユーザー | チャット | ✅ |
| 2 | 計画ページを作る | Claude | html-plan | ▶ いまここ |
| 3 | 計画を読んで決める | ユーザー | 計画ページ | ⬜ |

- 状態の印は4つだけ: ✅ 済み、▶ いまここ、⬜ まだ、⏳ 待ち（だれを待っているかも書く。例: ⏳ ユーザーの答え）
- 「だれ」は ユーザー / Claude / メンター など。「どこで」は チャット / スマホ / リポジトリ / GitHub / Slack など
- ユーザーはスマホで読む。ステップの名前は短く（10文字くらいまで）
- ▶ は1つだけ。ユーザーの番なら、そのステップを ▶ か ⏳ にして、何をしてほしいかを表のすぐ上に一言書く

## 4. 終わったら

- 全部 ✅ になったら、台帳の一番上に「終わった日」を書く
- 作業の中で出た疑問や課題は、台帳だけでなく docs/17 か docs/18 にも残す（CLAUDE.md の「最上位の考え」）
