# 週報

運営の決まり（名簿リポジトリの README。2026-10-25 に読んだ）:
- 置き場: `reports/koshihara-pharm/YYYYMMDD.md`（SingularitySociety/bootcamp004-02。参加者だけが見られる非公開リポジトリ）
- プルリクエスト（PR）を出し、マージされたら Slack で共有する
- **「相談事」と「サマリー」は、必ず人間が自分で書く。** AI が書いた文章は文脈が分かりにくく、ここが自分の考えと振り返りの中心になるため。ほかの欄は AI が書いてよい
- 11〜12月は毎週必ず出す。他の参加者へのフィードバックもする

## 1. 期間を決める

- 期間は「前の週報の次の日 〜 今日」。前の週報がなければ、ふだんは土曜〜金曜の7日間
- 前の週報は `gh api repos/SingularitySociety/bootcamp004-02/contents/reports/koshihara-pharm` で見る

## 2. タイムラインを集める（git と Claude の記録）

```
node .claude/skills/shuuhou/timeline.mjs 始めの日 終わりの日
```

出てくるもの:
- **Claude と作業した時間帯**: このフォルダでの会話の記録から、時刻だけを読む（話の中身は読まない）。20分以上あいたら別の作業として分ける
- **git のコミット**: いつ、何を記録したか

git で分かること・分からないこと（ユーザーに聞かれたら、この形で答える）:
- 分かる: コミットした日時と、何を変えたか。GitHub の画面（Commits）でも見られる。あとから消えない
- 分からない: 作業を**始めた**時刻、コミットしなかった作業（スマホで試す、資料を読む、Slack、考える時間）
- だから「始め〜終わり」は Claude の記録で補い、それでも入らない作業はユーザーに一言で聞く（例:「スマホで試した時間はありますか」）
- **作業時間は週報に書かない**（運営の決まりにない。2026-10-25 ユーザーと決定）。下書きを渡すときに、チャットで「今週は約○時間（目安は週16時間）」と一言見せるだけにする。タイムラインは「今週やったこと」を拾うために使う

コミットの言葉は英語なので、週報には、親から見て何が変わったかを日本語で書き直す。docs/17、docs/18 の変わったところ（`git diff 始めのコミット^ HEAD -- docs/17_kikanchu_yarukoto.md docs/18_iken_kiroku.md`）も見て、もらった意見と決めたことを拾う。

## 3. 下書きを作る

- 置き場: `private/shuuhou/YYYYMMDD.md`（private/ は GitHub に上げない設定）
- 形（運営の記入例に、ほかの参加者がよく足している欄を加えた）:

```markdown
# YYYY/MM/DD 週報 — 【名前】 (koshihara-pharm)

- 期間: YYYY/MM/DD 〜 YYYY/MM/DD
- コース: Vibe Coding
- プロジェクト: こどもおくすりサポート（子どもが薬を飲めるように親を手伝うスマホ用サイト）
  - サイト: https://koshihara-pharm.github.io/boot_camp/
  - リポジトリ: https://github.com/koshihara-pharm/boot_camp

## 今週やったこと
- （困りごと → 作ったもの → 確かめたこと、の順で。1行ずつ）

## 使われた数・もらった声
- （使われた数、親に「いくらなら払う？」と聞いた答え、もらった意見。なければ「まだない」と書く）

## 次にやること
- （小さく1〜3個）

## 相談事（※人間が書く）
【ここはご自分で書いてください】

## サマリー（※人間が書く）
【ここはご自分で書いてください】

## 他の参加者へのフィードバック（※人間が書く）
【ここはご自分で書いてください】
```

書き方（ほかの参加者の週報を読んで分かった、読みやすい週報の共通点）:
- 触れるもの（サイトの URL）を一番上に置く。読む人がすぐ試せる
- 「できた」と「まだ確かめていない」を分けて書く（例: 作った・スマホでは未確認）。盛らない
- 数で書けるものは数で書く（カードの数、テストした薬の数）
- 「今週やったこと」は親から見た変化で書く。ファイル名や技術の言葉は最小にする
- 長くしない。全部書きたいときは、細かいことをリポジトリの docs へのリンクにする
- フィードバックがほしいところは、何を見てほしいか（どの画面、何秒で読めるか）を具体的に書く

## 4. 人間が書く欄を手伝う（書かない）

- 「相談事」「サマリー」「他の参加者へのフィードバック」は、**Claude が文章を作らない。下書きや言い換えの案も出さない**
- 思い出す手がかりとして、事実だけを並べて見せてよい:
  - 今週つまずいたところ（会話やコミットから。例:「10/19 に〇〇でやり直した」）
  - docs/17、docs/18 に残っている疑問や課題
  - ほかの参加者の新しい週報で、相談事やフィードバックを求めているもの（名前、プロジェクト、何を見てほしいか、URL を1行ずつ）
- ユーザーがチャットに書いた文は、そのまま貼る。誤字を直すときは、直してよいか聞いてから

## 5. 守ること（出す前に見る）

- 子どもや家族の名前・年齢・病気、勤め先の薬局、患者さんのことを書かない。名簿リポジトリは非公開だが、公開と同じ扱いにする
- 薬の説明は、サイトに出している出どころのある内容だけにする
- 本名は名簿と同じ書き方にする。boot_camp（公開リポジトリ）には、本名を書いた下書きを入れない

## 6. 出す（ユーザーが「出して」と言ってから）

1. 名簿リポジトリを、boot_camp の外（となりのフォルダ `../bootcamp004-02`）に置く。なければ `gh repo clone SingularitySociety/bootcamp004-02`、あれば `git pull`
2. ブランチ `report-koshihara-pharm-YYYYMMDD` を作り、`reports/koshihara-pharm/YYYYMMDD.md` に置く
3. コミットして push し、PR を出す（題: `週報 YYYY/MM/DD (koshihara-pharm)`）。push と PR の前に、何をするかを一言伝える
4. マージするかはユーザーが決める
5. マージされたら、Slack で共有する文の下書きを出す（どのチャンネルかはユーザーに聞く）。送るのはユーザー

## 7. 出したあと

- 週報への返事やコメントが来たら、スキル fb-triage で docs/18 に記録する
- 週報を書いていて出た疑問や課題は docs/17 にも残す（CLAUDE.md の「最上位の考え」）
