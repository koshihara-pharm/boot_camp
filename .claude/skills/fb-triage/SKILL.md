# FB のトリアージ

意見をもらったら、**記録する → 仕分ける → 優先度をつける → ユーザーが決める**、の順に進める。
決めるのはユーザー。このスキルは案を出すところまで。

## 1. 記録する（docs/18）

- docs/18_iken_kiroku.md の一覧の表と、下の詳しい欄に1件足す
- 書くこと: 日付、だれから、どこで、意見の要点、どう使うかの案、区分、優先度、状態
- だれから: 名字と立場（例: 田沼さん（参加者兼メンター））。名前が分からない、または書かないときは立場だけ（例: 参加者（薬剤師））。分からなければユーザーに聞く
- 原文は貼らず要点にする。ユーザーの本名、子どもや家族のこと、勤め先の薬局のことは書かない（リポジトリは公開と同じ扱い）
- 1つの投稿に意見が2つ以上あれば、分けて記録する

## 2. 仕分ける（区分）

| 区分 | どんな意見か | 行き先 |
|---|---|---|
| **安全** | 医療上の判断、個人情報、薬の情報の出どころ・許可に関わる | 何より先にユーザー（薬剤師）に見せる。CLAUDE.md の「守ること」と照らす |
| **機能** | 作るもの、直すもの（画面、検索、データ） | docs/19 の「次に足す候補」か docs/17 |
| **考え方** | 進め方、作り方、プロダクトの考え方の助言 | CLAUDE.md の「最上位の考え」「基本理念」「基本方針」「進め方のメモ」 |
| **確認** | 意味がはっきりしない、前提が分からない | 相手に聞き返す文をユーザーに出す |

## 3. 優先度をつける

次の問いに順に答えて決める。

1. **安全に関わるか**（区分が「安全」）→ はい なら **高**
2. **それで子どもが飲むようになるか**（CLAUDE.md の物差し）→ いいえ なら **低**（今は作らない。理由を書いて「見送り」か「保留」）
3. **入口で止まっていないか**（例: 薬が検索で見つからないと、ほかの機能が全部使えない）→ はい なら **高**
4. **小さく作れるか**（1回の作業で作って、スマホで確かめられるか）→ いいえ なら、小さく分けた最初の1つだけを候補にする（基本理念: 大きな仕様を一気に作らない）
5. **作り直しが高いか**（端末に保存するデータの形、資料の出どころと許可、個人情報）→ はい なら、作る前にユーザーと決める
6. 上のどれでもなければ **中**

あわせて見ること（CLAUDE.md「基本方針」の心がまえ 6、7）:
- 意見を言った人が、**今このサイトを使っているか、お金を払うか**。今使っている人の困りごとは重く見る
- 「○○があれば使う」「よさそう」だけでは優先度を上げない。立場のある人の意見でも同じ
- 確かめられるなら、その人に「今どう使っているか」「いくらなら払うか」を聞く文を、返事の下書きに入れる

## 4. トリアージの HTML を更新する

- docs/fb_triage.html を docs/18 に合わせて直す: 上の数（意見の数、高、検討中、反映した）、意見のカード（優先度の高い順。反映したものは下）、日付
- 直したら、ブラウザで開いて見せる
- ユーザー自身の考え（FB ではない）は docs/17 の「ユーザーがやりたいこと」に書き、HTML の「自分のやりたいこと」に出す。仕分けと優先度のつけ方は FB と同じ

## 5. ユーザーに出す

- 仕分けの結果を短く出す: 区分、優先度、理由（1行）、次の一歩（小さく1つ）
- やるかどうかはユーザーが決める。決まったら CLAUDE.md の「決まったこと」か docs/17 に移し、docs/18 の状態を「反映した」にする
- 相手への返事: Slack は12時間以内に反応する決まり（docs/16）。お礼と「どう使うか」を一言入れた返事の下書きを出す。送るのはユーザー

## 状態

**未対応** / **検討中** / **反映した**（どこに） / **保留**（いつ見直すか） / **見送り**（理由）
