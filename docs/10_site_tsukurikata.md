# サイトの作り方

- 作成: 2026-10-12
- こどもおくすりサポートは、2 つの部分でできている

| 部分 | 中身 | 作り方 | 置き場所 |
|---|---|---|---|
| アプリ | 薬を選ぶ、混ぜていいか、飲ませ方のコツ、おくすり記録、のめた！スタンプ | `index.html` と `data.js` の 2 ファイル。サーバーなし | このリポジトリ（GitHub Pages で公開している。https://koshihara-pharm.github.io/boot_camp/ ） |
| 読み物ページ | なぜつくったか、できること、飲ませ方のコツ、混ぜるときの基本、記録と安全、つくった人、出どころ | Notion で書き、Wraptas で Web サイトにする | Notion「こどもおくすりサポート」（非公開の下書き）→ Wraptas |

読み物ページは、検索や SNS から人が入ってくる入口。そこからアプリへリンクする（docs/04 の「先に役立つものを見せる」、CLAUDE.md の「まず人を集める」）。

読み物ページの作り方は、ユーザーの別リポジトリ homepage_small_business（薬局向け Web 制作。非公開）の「フェス型ペライチ」（`templates/format_event-onepage.md`、`.claude/skills/build-event/SKILL.md`）にならった。

## 1. アプリ（index.html と data.js）

### ファイル
- `index.html`: 画面と動き。見た目の色は先頭の `:root` で決めている（青緑の地、黄色のスタンプの丸）。ダークモードにも対応
- `data.js`: 中身のデータ
  - `SOURCE`: 混ぜていいかの元資料（資料名、改訂日、URL）
  - `FOODS`: 食べ物 12 種類（元資料の列の順）
  - `DRUGS`: 薬 33 種類。`foods` は飯塚病院の表の記号（`o` ○、`x` ×、`ox` ○/×、`ov` ○/▼、`xv` ×/▼、`-` データなし、末尾 `*` はメーカー推奨）。飯塚病院の表にない薬は `foods: null`
  - `NCCHD_SOURCE`、`NCCHD_FOODS`、`NCCHD_ROWS`: 2 つ目の表（国立成育医療研究センター 2018年）。`drug` がアプリの薬の名前、記号は `o` ●、`s` ▲ 変わらない、`x` ×、`-` データなし
  - `HOWTO`: 飲ませ方のコツ（出どころつき）
  - `STAMPS`: スタンプの絵

### よくある変更
| やりたいこと | 直す場所 |
|---|---|
| 薬を足す | `data.js` の `DRUGS` に 1 件足す。記号は元資料と照らし、薬剤師が確認する（docs/07） |
| 飲ませ方のコツを足す・直す | `data.js` の `HOWTO`。出どころの URL を必ずつける |
| スタンプの絵を変える | `data.js` の `STAMPS` |
| 色を変える | `index.html` の `:root`（明るい画面）と、その下の 2 か所（暗い画面） |

`data.js` を直したら、`index.html` の `<script src="data.js?v=日付">` の日付も、その日に変える。変えないと、ブラウザが前に読んだ古い `data.js` を使い続け、直したことが画面に出ない（2026-10-26、一般名を足したときにつまずいた）。

### 記録の保存
- 服用中の薬とスタンプは、ブラウザの中（localStorage の `okusuri.meds.v1` と `okusuri.stamps.v1`）だけに保存する。サーバーには送らない
- 家族・保育園へは、親が「LINEで送る」か「文章をコピー」を押したときだけ文章が外に出る

### 動作の確かめ方（Claude Code に頼むとき）
- スマホの幅（390px）のブラウザで、次を通しで操作して確認する
  1. 薬を探す（ひらがなでも見つかる）→ 薬のページで、味、混ぜていいか、飲ませ方のコツが出る
  2. 「この薬を『おくすり記録』に入れる」→ 時間・量・日数を入れて追加
  3. 「のめた！」を日数 × 回数ぶん押す → 最後に「さいごまで のめたね！」
  4. 「家族に」「保育園に」の文章が出る。「LINEで送る」のリンクができる
  5. 再読み込みしても記録が残っている
- 横にはみ出していないこと（ページの幅が画面の幅と同じ）

### プレビュー（自分だけが見る）
- claude.ai のアーティファクト（https://claude.ai/artifact/VdxY8vxHE5Mo1Wf6y7bLTX ）。`index.html` から `<!doctype>`・`<html>`・`<head>`・`<body>` の外枠を外し、`data.js` と一緒に載せている。Claude に「アーティファクトも更新して」と頼むと、同じ URL のまま新しくなる

### 公開（誰でも見られる）: GitHub Pages
- **公開している**（2026-10-25 に確かめた）: https://koshihara-pharm.github.io/boot_camp/ 。`main` ブランチの `/ (root)` を出している
- 設定の場所: GitHub のリポジトリ画面 → Settings → Pages（Source は「Deploy from a branch」、Branch は `main`、フォルダは `/ (root)`）

更新のしかた:
1. 作業ブランチで直す
2. main にまとめる（Claude にプルリクエストを作ってもらい、GitHub の画面でマージ）
3. 数分後に、上の URL に反映される
4. main にまとめる前に、docs/07 のデータ確認を済ませる。病院の表はまるごと載せず、docs/07 の「資料の使い方の方針」の形にする（許可は頼まない。2026-10-18 ユーザー決定）

### 使われた数を数える: Microsoft Clarity と Google アナリティクス
- `index.html` の head に、2つのコードを入れている（くわしい経緯は docs/17 の 6）
  - **Microsoft Clarity**（プロジェクト「こどもおくすり」、ID `z5py1akpjj`）: 押された場所の色分けと、画面の録画。2026-10-30 に入れた（PR #18）。入力欄の文字は Clarity がいつも隠す
  - **Google アナリティクス（GA4）**（プロパティ「子どものお薬サポート」、測定 ID `G-1SGGXK56V6`）: 開かれた数、来た人の数、スクロール、外へのリンク。2026-10-31 に入れた（PR #23）。結果は GA4 の「レポート」→「リアルタイム」ですぐ見られる
- 2つとも、使っていることをページ下の「このサイトについて」（たたんだ形）に書いている。規約で知らせることになっているので消さない
- 検索欄に入れた文字（薬の名前）は送らない。URL に入るのは `#drug-3` のような番号だけ。URL に薬の名前などを入れる直しをするときは、先にここを見直す
- Google Tag Manager（どのボタンが押されたかを細かく数える）は、使う人が増えてから入れる（2026-10-31 ユーザーの判断）。入れるときは、今の GA4 のコードを Tag Manager に移す（二重に数えないため）

## 2. 読み物ページ（Notion + Wraptas）

### Notion のページ
- 「こどもおくすりサポート」: https://app.notion.com/p/3f7d62ff1e0081cda91ce9afe80f7d36 （2026-10-12 作成。今は非公開の下書き）
- 構成（上から）: ヒーロー（キャッチ＋説明＋カード3つ）→ WHY なぜつくったか → FEATURES できること → HOW TO 飲ませ方のコツ → MIX 混ぜるときの基本 → SAFETY 記録と安全について → ABOUT つくった人 → SOURCES 出どころ → 編集メモ（トグル。公開前に消す）

### 書き方のきまり（homepage_small_business の型と同じ）
- 見出し 2 は `<span color="blue">英字</span>和文` の 2 階建て。Wraptas はこの見出しごとにセクションを分け、背景を交互に変える
- 絵文字のアイコンは使わない（ページアイコン、コールアウトのアイコンも）。コールアウトは色だけで意味を分ける
  - 青: アプリを開く（主な行き先）、緑: 飲ませ方、紫: つくった人、オレンジ: できること、灰: 注意書き
- 事実（数字、調査、薬の情報）は出どころのあるものだけ。分からないことは `【要確認】` と書き、末尾の編集メモに並べる
- 医療のページなので、治ることを約束する言い方、割引やキャンペーン、体験談の「効いた」は載せない
- 内部向けのリンク（社内の Notion、営業の資料）は載せない

### Wraptas に載せる
見た目の CSS とツールの設定は、このリポジトリの `wraptas/` にある。

| ファイル | 中身 |
|---|---|
| `wraptas/okusuri-theme.css` | 読み物ページの CSS。フェス型の CSS をコピーし、色（青緑と黄）と書体（Zen Maru Gothic）だけ変えた。`--accent` と `--ink` で着せ替えられる |
| `wraptas/tasks.okusuri.json` | homepage_small_business の `tools/wraptas/apply.mjs` 用の設定（ひな形） |

手順:
1. **公開先を決める**: sumobiji-ph.jp の下（例 `/okusuri`）に置くか、別の Wraptas サイトを作るか（別サイトは月額がかかる。薬局向けの事業とは見せ方が違うので、どちらがよいかは要相談）
2. **Notion で「Webで公開」をオンにする**: 公開先のサイトの Notion の公開ツリーの下にページを移す（または Notion の共有メニューから Web 公開）。`notion.site` の URL で開けることを確かめる
3. **設定ファイルを用意する**: `wraptas/tasks.okusuri.json` を homepage_small_business の `tools/wraptas/` にコピーし、`<>` の所（サイト名、siteId、notion.site の URL、CSS の場所）を埋める
4. **試しに流す**: `node apply.mjs tasks.okusuri.json --dry` → スナップショットで確認
5. **本番**: `node apply.mjs tasks.okusuri.json`。反映は 5 分ほどかかる
6. **検品**: `node typocheck.mjs <公開URL> 1280` と `… 390`（日本語の折り返しの崩れ、はみ出し）→ `node snapshot.mjs <公開URL> okusuri_sp 390` で目で見る。シークレットウィンドウ（ログインなし）とスマホの実機でも開く
7. **アプリへのリンクを入れる**: GitHub Pages の URL が決まったら、Notion のヒーローの「アプリを開く」に入れ、編集メモの該当行を消す

手作業でやる場合は、Wraptas の管理画面 → ページ設定 → パーマリンクを追加 → 「このページ専用の追加CSS」に `okusuri-theme.css` の中身を貼る。サイトデザイン編集の「セクションを区切るブロック」が h2 になっていること。
