- 細かい数字や決定は、元のリポジトリの CLAUDE.md が正しい。ここは要約

## 何をしているか

薬剤師として働きながら、**薬局向けの Web ページ制作を副業で始めている**。

- 商品: 薬局のホームページ、採用ページ、公式 LINE の構築（リッチメニュー）
- 作り方: 中身は Notion。見た目は Wraptas（Notion をサイトにするサービス）と自作の CSS。納品後は薬局が自分で更新できる形にする
- 公開しているサービス紹介サイト: https://sumobiji-ph.jp/ （独自ドメイン、Google Search Console に登録済み）
- 実績: 公式 LINE の初期設定を 1 件受注（知人の店。リッチメニュー 1 面）。薬局のホームページ・採用ページの公開デモを複数作成

## Claude Code で作った仕組み（Vibe Coding の実績）

リポジトリの中に、Claude Code のスキル（作業の手順書）と自動化ツールを作っている。

| 作ったもの | 中身 |
|---|---|
| `/make-demo` | 薬局の公開情報から、採用ページのデモを作る |
| `/build-hp`、`/build-gi`、`/build-event` | 薬局のホームページ、採用サイト、イベント告知ページを Notion に作り、Wraptas で公開するまでを一気に進める |
| `/build-line` と `tools/line/` | 公式 LINE のリッチメニューの画像作成と設定 |
| `/qa-page` | 公開ページの崩れ（日本語の折り返し、はみ出し、文字の重なり）を機械で検品する |
| `/search-register` | 検索エンジンへの登録と、公開範囲の点検 |
| `/lead-research` | 営業先の薬局の調査 |
| `tools/gas/` | Google Apps Script のメール下書きの仕組み |
| `tools/muumuu/` | ドメイン（ムームードメイン）の設定の自動化 |
| `templates/`、`patterns/` | 薬局向けのページの型と CSS のパーツ集 |

ほかに、市場調査（競合の価格、安く自分で更新できるサイトの市場、薬局サイトの構成の実測、採用ページへの導線）を docs にまとめている。

## 公開して大丈夫かの点検（2026-10-12）

2026-10-10 時点のファイル（最新の 1 コミット分）を点検した。過去の履歴は取得できず未点検。2026-10-12 の時点で、このリポジトリは外から読めなくなっていた（非公開に切り替えた可能性）。

問題なし:
- パスワード、API キー、トークンは入っていない（ログインは人がする設計）
- Google の所有確認コード（DNS に出ている値）、`package-lock.json` のハッシュは公開されても問題ない

公開すると問題になるもの:
- **営業先リスト**（`tools/gas/src/Data.gs`）: 実在の薬局 20 件ほどの名前、メールアドレス（個人のフリーメールらしきものを含む）、営業メールの下書き、送信済みかどうか、各薬局についてのメモ
- **ユーザー個人のメールアドレス**（`tools/gas/README.md`）
- **実在の薬局のデモページの場所と電話番号**（`tools/wraptas/tasks.*.json`）。「閲覧のみ・非公開リンク限定」という自分のルールと食い違う
- 社内用の Notion の URL（20 件以上）、Google フォームの編集用 URL（`CLAUDE.md`）。開くには権限が要るが、出さないほうがよい

応募での扱い（案）:
- 元のリポジトリは非公開のままにする
- 実績として見せるのは、公開サイト https://sumobiji-ph.jp/ と、営業先リストなどを除いた「見せる用」の新しいリポジトリ（スキルやツールの仕組みだけ）。履歴に残った情報を持ち込まないよう、新しいリポジトリは履歴なしで作る

## このプロジェクトに使えるもの

- Wraptas と Notion の知識 → 読み物ページ（飲ませ方の詳しい版、薬ごとの解説、なぜ作ったか）を作るとき
- 公式 LINE の構築 → 将来、このサイトを LINE から開ける・LINE で知らせる形にするとき
- `/qa-page` の考え方 → このサイトのスマホ表示の検品
- 「保守で詰まる構成は選ばない」という方針 → このサイトもサーバーなしの 2 ファイル構成にしている
