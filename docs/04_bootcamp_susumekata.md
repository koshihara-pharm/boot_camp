## 1. デモの作り方（demo.md）

### 考え方
- 完成版を作ろうとしない。価値の芯だけを入れた最小のもの（MVP）を作る。アプリでなくてもよい
- 「手を動かす → 何かが動く → 誰かが反応する」の繰り返しが、続けられる唯一の方法
- ゴールは大きくてよい。ただし、目の前の作業は小さく

### 最初に作るものの例
- HTML 1枚で動くデモページ
- LP（どんなサービスかを説明する1ページ）
- Google フォーム + Notion でできる簡単なサービス
- ほかに CLI ツール、プレスリリースのひな形、API の仕様と仮の実装

### 「触れるデモ」で十分
- ログイン、本番のデータベース、アクセス集中への備えはいらない。価値があると分かってから作る
- ボタンを押すと、それらしく動けばよい
- データは全部固定でよい
- 裏側は人の手作業でもよい（Wizard of Oz と呼ばれるやり方）

### 回し方
1. 小さく作る
2. 使ってほしい人 3〜5人に見せる
3. 反応を見る
4. 次の小さなものを作る

### 失敗するパターン
- 議論だけが続く
- 仕様書だけが増える
- 完成形を一気に作ろうとする
- 誰にも見せないまま半年たつ

### その他
- Slack で、デモと評価をこまめに出し合う（月1の報告とは別）
- 1人より 3〜5人のチームを強く勧めている。ただし第4回2期の募集要項では「相互サポートグループ（共同開発ではない）」の形

## 2. プロダクトについて（Product.md）

- アイデアだけには価値がない。作って使ってもらって初めて価値になる
- 同じアイデアは1万人が思いついている。秘密にせず共有してフィードバックをもらう
- みんなが褒めるアイデアは、もう遅いかもしれない。批判が多いアイデアに可能性があることも
- 作って使うことでしか、アイデアは磨けない。早く試して早く失敗する。まず簡単な方法で試す
- 推測ではなく、数字で評価できる仕組みを作る
- ドッグフーディング: 最初のユーザーは自分。自分で使う
- フィードバックの聞き方
  - 真剣に使ってくれる人の意見が一番大事。肩書は関係ない
  - 「○○があれば使う」と言う人は、○○を足しても使わない。条件付きの意見は聞かなくてよい
  - 「○○がほしい」と言われたら「いくらなら払う？」と聞く。具体的な金額が出なければ思いつき
  - フィードバックをくれるユーザーはとても大事。普通の人は黙って使わなくなるだけ

## 3. 応募前のチェックリスト（tips.md）

主に企業向けアクセラレーターの話。今回に関係するもの:
- プログラムの目的と選考基準を把握する
- 過去の参加者を調べて共通点を見る。過去の参加者に話を聞く
- 応募内容を、プログラムの目的に合わせて書く

## 4. サービスの広め方（promotion.md）

- 「誰に届けたいか」でチャネルを選ぶ。全部やる必要はない
- 最初の100人は、直接声をかける、話を聞く、使い方を横について教える、で集める
- 流入数ではなく、登録や継続利用で効果を見る
- 宣伝より先に、コミュニティで質問に答えるなど貢献する
- 日本向けの順番: (1) 知り合い・想定ユーザーに直接見せる (2) X で開発ログを毎日 (3) Zenn に技術記事 (4) note に「なぜ作ったか」 (5) 関連コミュニティで質問に答える (6) YouTube Shorts でデモ動画
- 一般向け（B2C）に効くのは YouTube、TikTok、Instagram Reels
- やってはいけない: いいねや票の購入、身内のサクラ

## 5. 募集ページで強調されていること（docs/01 の補足）

- 「業務知識をもった非エンジニアこそが、これから最も必要とされます」
- 「エンジニアやベンチャーがまだ目をつけていない業界で働いている人ほど、大きなチャンスがあります」「あなたしか知らない課題を、あなた自身の手で解決するツールを作ろう」
- 1期では Supabase や Firebase を使った Web アプリ、手元で動くツールなどが作られた
- 採用されたらすぐ Slack に合流し、その時点から開発を始める
- 10月下旬のオンライン開始で、作ったプロトタイプを見せ合う

## このプロジェクトへの当てはめ

1. **応募用のプロトタイプは「スマホで開ける HTML 1枚」で足りる。** ログインもデータベースもいらない。データは端末の中か、固定のサンプルで動けばよい
2. **困りごとの確かめ方も決まっている。** ママ・パパ 3〜5人に、デモか聞き取りメモ（docs/03）を見せて反応を見る
3. **聞くときの注意。** 「あったら使うかも」は数えない。「今週これで困った」という実際の話を集める
4. **自分が使う。** 発表では「うちでは（または薬局の窓口では）こう使っています」と言えるようにする
5. **業界の中にいる強み。** 子どもの薬の現場を知っている立場なら、それを「作りたいもの」の欄にそのまま書く
6. **広め方。** まずは知り合いのママ・パパに直接見せる。次に note に「なぜ作ったか」を書く。ママ・パパに届けるなら Instagram や YouTube のほうが合う可能性がある
