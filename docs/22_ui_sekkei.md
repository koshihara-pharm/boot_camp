## 原文の要点

### 三つの合言葉（いちばん大事）

| 合言葉 | 意味 |
|---|---|
| **一貫性をもたせる** | 同じ意味のものは、同じ見た目・同じ場所・同じ言葉で |
| **読まなくても分かる** | 説明文を読まなくても、見れば何ができるか分かる。文字を減らすのであって、なくすのではない |
| **肯定形と否定形をまぜない** | 項目は「〜する」の形にそろえる |

### 第1章 一貫性

- そろえるのは4つ: 見た目（色・形・大きさ）、場所、言葉、振る舞い（同じ操作は同じ結果）
- 内側（自分のサイトの中）と、外側（世の中の慣習。虫眼鏡は検索、× は閉じる、下線はリンク）の両方をそろえる。独自の見せ方より、まず慣習に合わせる
- 一貫していると、利用者は一度覚えたことを次の画面に当てはめられる（頭の中の絵＝メンタルモデルができる）

### 第2章 読まなくても分かる

- 人は画面の文を読まない。拾い読みする。説明文で補っても、その説明文が読まれない
- 押せるものは押せそうに見せる（枠、色、下線）
- 利用者の記憶に頼らない。前の画面で見たものは、必要な場所でもう一度見せる
- アイコンには言葉を添える。アイコンだけにすると、かえって分からない
- 確かめ方「3秒テスト」: 初めての人に3秒だけ見せて「この画面で何ができる？」と聞く（原文の提案。出典のある手法ではない）

### 第3章 言葉とスイッチ

- 利用者がふだん使う言葉にする。内部の言葉、業界の言葉を出さない
- 項目は肯定形にそろえる。二重否定は使わない
- スイッチは「切り替えた瞬間に効く二択」だけ。複数選ぶならチェックボックス、1つ選ぶならラジオボタン
- ボタンは動詞で、押すと何が起きるか分かる言葉に（「OK」「はい」ではなく「削除する」「残す」）
- 入力欄の名前は欄の上に置く。欄の中の薄い入力例で代わりにしない（書き始めると消えるため）

### 第4章 状態を伝える・間違いを防ぐ

- 押したら、押したと分かる。待たせるなら、待っていると分かる
- 間違えて押しても、すぐ抜け出せる。いちばんよいのは「元に戻す」
- 間違えられない形にする（選べないものは選べなくする）
- エラーの文は、起きた場所のそばに、利用者の言葉で、直し方つきで。入力は消さない。利用者を責めない
- 確認の画面は、取り消せない大事な操作の前だけ。出しすぎると読まれない

### 第5章 配置と量

- 近いものは仲間に見える。関係あるものは近く、関係ないものは離す
- 大きく近いものは押しやすい。よく押すものは大きく、危ないものは離す
- 選択肢が多いほど迷う。よく使うものを1〜3個にしぼって前に出す
- 1つの画面の主役（いちばん大事なボタン）は1つ。余白はまとまりと主役を伝える道具

### 第6章 誰でも使える

- 色だけで区別しない。言葉や形も足す
- 文字と背景の濃さの差（コントラスト比）: ふつうの文字は 4.5 対 1 以上、大きな文字は 3 対 1 以上（WCAG）
- 文字を大きくしても崩れない
- キーボード（Tab キー）だけで最後まで操作でき、いまどこにいるかが見える
- 画像とアイコンには、読み上げ用の言葉（代替テキスト）を付ける
- 日差しの下、片手がふさがっている、などの「条件の悪いとき」に使えるかは、全員に効く

### 第7章 迷わせない

- 「いまどこ？」「次に何をする？」を画面から分かるようにする。手順が何段階かあるなら、いま何番目かを出す
- 画面の中に「戻る」ボタンを作らない。来た道を戻るのはブラウザの仕事。リンクが要るなら「ホームへ」のように行き先を書く（原文の勧め。入口はあとから増えるため）
- 1秒より長く待たせるなら、処理中だと見せる
- 何も出ないとき（検索で見つからない など）も「状態」のうち。いまの状態と、次にできることを出す
- 利用者の頭の中の絵に合わせる。操作する場所と結果が出る場所を近くに。モード（同じ操作の意味が場面で変わる）を作らない
- 最初は少なく見せ、たまに使うものは折りたたむ。**ただし大事な注意は折りたたまない**
- よい初期値を入れておく。人は初期値をそのまま使う
- 説明が要るなら、迷う場所のそばに1行で

### 第8章 操作させない・失わせない

- システムが分かることは聞かない。同じことを二度聞かない
- 値を打たせるより、結果を選ばせる
- 書き方の違い（全角・半角、ひらがな・カタカナ、ハイフン）で突き返さない。そろえるのはシステムの仕事
- 条件があるなら、エラーの前に書く
- 入力したものは利用者のもの。途中で閉じても消えない。自動保存か保存ボタンか、サイトの中で1つに決める
- ログインとパスワードの決まり（表示の切り替え、貼り付けを禁止しない、メールアドレスを二回聞かない、など）

### 第9章 AI に画面を作らせるときの見方

- AI がいちばん崩しやすいのは一貫性。画面ごとに言葉・色・配置が少しずつ変わる。対策は、部品を共通にすることと、使う言葉の一覧を先に渡すこと
- 守らせたい原則は、口で毎回頼まず、毎回読まれる場所（CLAUDE.md など）に書く
- できた画面は、コードを読む前に開いて、次の順に見る: 3秒テスト → 言葉 → 一貫性 → 操作の結果 → 配置 → 誰でも → 流れ → 入力
- 直すときは、画面を直させるより先に、ルールを足す。**同じ指摘を二度したら、ルールにする合図**
- 回し方: ルールを書く → AI が作る → チェックリストで見る → 直しをルールに足す → 最初へ

## このプロジェクトへの当てはめ

### 迷ったときの順番

1. CLAUDE.md の「守ること」（医療上の判断をしない、出どころを書く、個人情報を入れない）
2. CLAUDE.md の「決まったこと」（ユーザーが触って決めた画面の形。例: トップのボタン4つ、見出しの言葉）
3. このファイル（原文の原則）

2 と 3 が食い違ったら、Claude は勝手に直さない。「原文ではこう、今はこう」を並べて、ユーザーが決める。決まったら下の「このサイトの画面ルール」か CLAUDE.md に書く。

### このサイトで特に効くところ

使う人は、子どもを抱えながら片手で、数秒で済ませたい親（CLAUDE.md）。そのため、次の原則を特に重く見る。

| 原則 | このサイトでは |
|---|---|
| 3秒テスト（第2章） | トップを3秒見て「薬の名前を入れると、味と混ぜていい食べ物が分かる」と言えるか |
| 押しやすさ（第5章） | 片手の親指で押せる大きさ。小さい文字だけのリンクにしない |
| 主役は1つ（第5章） | トップの主役は検索欄。ボタンを増やすときは、何かを減らせないか先に考える |
| 利用者の言葉（第3章） | 薬局の言葉（散剤、DS、服用）ではなく、親の言葉（粉薬、飲ませる）。親が読む文は漢字かなまじり（CLAUDE.md） |
| 書き方で突き返さない（第8章） | 薬の名前は、ひらがな・カタカナ・全角・半角のどれで入れても見つかる |
| 空の結果（第7章） | 見つからないとき、次にできることを出す |
| 色だけで区別しない（第6章） | 「混ぜていい」「避けたい」は色だけでなく言葉と印でも分ける |
| 大事な注意は折りたたまない（第7章） | 医師・薬剤師に相談する案内は、開かなくても見えるところに |
| 戻るボタン（第7章） | 原文は「戻る」を作らず、行き先（「ホームへ」など）を書くことを勧める |

### 今は当てはまらないところ

- ログイン、パスワード、会員登録（第8章の4）: このサイトにはない
- 設定のスイッチ、保存（第3章、第8章の3）: このサイトは何も保存しない（2026-10-25 に記録を外した）
- 記録やログインを足すときに、その章を読み直す

## このサイトの画面ルール（育てるところ）

原文の第9章の例から、このサイトに当てはまるものだけを選んだ。同じ指摘が2回出たら、ユーザーが決めて、ここに1行足す。

- ボタンの言葉は、押すと何が起きるか分かる言葉にする（「OK」「はい」は使わない）
- アイコン（絵文字）には必ず言葉を添える。絵文字は読み上げない設定にする（aria-hidden）
- 色だけで区別しない。文字と背景のコントラスト比は 4.5 対 1 以上
- ボタン・見出し・入力欄は、今ある形を使い回す。画面ごとに新しい形を作らない
- 1つの画面の主役は1つ
- 移動のボタンは、行き先が分かる言葉にする（今の「← 戻る」をどうするかはユーザーが決める。下の確認結果を見る）
- 書き方の違い（ひらがな・カタカナ・全角・半角）で突き返さない
- 見つからないときは、次にできることを出す
- 大事な注意（医師・薬剤師への相談）は折りたたまない

### 使う言葉の一覧（そろえる）

同じものを画面ごとに違う言葉で呼ばない。新しい言葉を使う前に、ここを見る。

| 使う言葉 | 使わない言葉 |
|---|---|
| 粉薬 | 散剤、こなぐすり、ドライシロップ（薬の名前の中は別） |
| 飲ませ方 | 服用方法、のませかた |
| 混ぜていい | 混合可、配合 |
| 薬の味 | 味覚 |
| ストロベリー味、オレンジ味（薬についている味） | ストロベリー風味、オレンジ風味（2026-11-03 にそろえた） |
| 苦さ | 苦味（2026-11-03 にそろえた） |
| スポーツ飲料 | スポーツドリンク（2026-11-03 にそろえた。サイトの中で多いほうに合わせた） |
| ブックマーク（サイトの中に残す。「この薬をブックマーク」「ブックマークした薬」） | 保存、お気に入り（2026-11-07 ユーザーの判断） |
| 画像を保存（写真に残す。「この薬の画像を保存」「この飲ませ方の画像を保存」） | 情報を保存、ダウンロード |

薬の名前と資料の題名の中の言葉は、一覧と違ってもそのままにする（例: ビオフェルミン散剤、「散剤と飲食物の飲み合わせ」）。コードの中のメモ（画面に出ない）は直さなくてよい。

## これまでの確認の結果

### 2026-11-14（0〜1歳「スポイトで少しずつ」に、動画のボタンを足した。手元（localhost）でだけ。幅 375px）

変える前: 足すボタンは、今ある横長のボタン（左に絵、まん中に「▶ 動画で見る」と長さ）と同じ形・同じ言葉。ルールとぶつからない。変わるのは長さの文字だけ（この動画は 49.6秒なので「約50秒」。長さは動画ごとに出すようにした。今までの6本は「約40秒」のまま）。

| 観点 | 結果 | 見つかったこと |
|---|---|---|
| 3秒テスト | ○ | 赤ちゃんの絵と「▶ 動画で見る」「約50秒」で、動画があることと長さが分かる |
| 言葉 | ○ | 今までと同じ「動画で見る」。長さだけ「約50秒」 |
| 一貫性 | △ | ボタンの形は同じ。0〜1歳の3つのうち、動画があるのはスポイトだけ（哺乳びんの乳首とお薬だんごは、まだ絵だけ） |
| 操作の結果 | ○ | 押すと「0〜1歳・スポイトで少しずつ」の動画の画面が出る。動画は読めた（49.6秒、720×1280）。エラーなし |
| 配置 | ○ | ボタンは 314×141px（幅 375px のとき） |
| 誰でも | ○ | 色と字は変えていない。ボタンの名前は「この飲ませ方を動画で見る（約50秒）」 |
| 流れ | △ | 0〜1歳にも動画が1本できた。やり方を開く前は、動画があるか分からないのは前と同じ |
| 入力 | — | 入れる所は無い |

画面の写真は撮れなかった（ブラウザの画面が裏に回っていた）。ページの中身を読んで確かめた。△ は、残りの2本を作れば消える。

同じ日の続き: ユーザーがスポイトの絵を見て「正しい。次へ」。「哺乳びんの乳首」（47.9秒、「約50秒」）と「お薬だんご」（40.4秒、「約40秒」）にも同じボタンを足した。0〜1歳の3つとも、ボタンが出て（313×141px）、押すと動画の画面が開き、動画が読めた。エラーなし。画面の写真でも確かめた。一貫性と流れの △（0〜1歳は動画が1本だけ）は消えた。残るのは「食べ物に混ぜる」だけ。

### 2026-11-13（4回目。動画のサムネイルを、小さい横長のボタンにした。手元（localhost）でだけ。幅 390px）

きっかけ: 3回目の縦長のサムネイル（329×489px）を見て、ユーザーが「サムネでかすぎ、文字が見えないのは微妙」。3回目の △（配置）がそのまま当たった。
変えたこと: トップのお困りごとと同じ、横長のボタンにした。左に小さな絵（104×119px。動画の最初の画面から、子どもとうさぎの所を切り取る）、まん中に「▶ 動画で見る」と「約40秒」、右に「›」。押すと動画が出るのは同じ。

| 観点 | 結果 | 見つかったこと |
|---|---|---|
| 3秒テスト | ○ | 子どもの絵と「▶ 動画で見る」「約40秒」で、動画があることと長さが分かる |
| 言葉 | ○ | 「動画で見る」は前と同じ。「約40秒」は新しく足した（6本とも 37〜43秒） |
| 一貫性 | ○ | トップのお困りごとの、横長のボタン（左に絵、まん中に言葉、右に「›」）と同じ形。2回目・3回目の △（新しい形）が消えた |
| 操作の結果 | ○ | 押すと動画の画面が出る。6つとも読めた |
| 配置 | ○ | ボタンは 329×142px。やり方を開くと、手順の3つの文と「画像を保存」まで、1画面（390×844px）に入る。3回目の △ が消えた |
| 誰でも | ○ | コントラスト比: 「動画で見る」5.29、「約40秒」5.33、「›」5.38（どれも 4.5 以上）。ボタンの名前は「この飲ませ方を動画で見る（約40秒）」 |
| 流れ | △ | 前と同じ。0〜1歳には動画が無い。やり方を開く前は、動画があるか分からない |
| 入力 | — | 入れる所は無い |

気になる所: 絵が小さいので、題名とうさぎの顔は読み取りにくい（題名は、すぐ上のやり方の名前と同じ）。動画のあるやり方では、手で混ぜている絵（img/howto）は出ない。
同じ指摘: 「絵が大きくて、文が見えない」は、2026-11-10 の「パッと見の文字が多すぎる」と向きは逆だが、どちらも「開いたときに、大事なものが1画面に入るか」の話。ルールにするかは、次に出たらユーザーに聞く。

### 2026-11-13（3回目。動画のサムネイルを、動画の最初の画面（子ども・うさぎ・題名）にした。手元（localhost）でだけ。幅 390px）

きっかけ: ユーザーが、動画の最初の画面を見せて「サムネはこれにしてほしい」。2回目は、やり方の絵（手で混ぜている絵）をサムネイルにしていた。
変えたこと: 動画のあるやり方（6つ）は、開くと、動画の最初の画面から切り出した絵（video/thumb/年齢-やり方.jpg。うさぎが最初の一言を言い終えて、にっこりしているコマ）が出る。絵を押すと動画が出る（形は2回目と同じ）。動画の画面でも、再生する前にこの絵を出す（前は黒い箱）。動画のあるやり方では、手で混ぜている絵は出なくなった。サムネイルの絵が読めないときは、やり方の絵に戻る。

| 観点 | 結果 | 見つかったこと |
|---|---|---|
| 3秒テスト | ○ | 子どもの顔、うさぎ、題名、「▶ 動画で見る」が一度に見える。何の動画かが分かる |
| 言葉 | ○ | 2回目と同じ「動画で見る」 |
| 一貫性 | △ | 2回目と同じ（絵を押せるボタンは新しい形）。動画のあるやり方と、ないやり方（0〜1歳、食べ物に混ぜる）で、開いたときの絵の種類と大きさが違う |
| 操作の結果 | ○ | 押すと動画の画面が出る。6つとも、サムネイルも動画も読めた。再生する前に絵が出るので、黒い箱にならない |
| 配置 | △ | サムネイルが縦長（329×489px）。幅 390px の画面では、開いたときに手順の文が画面の下に下がる（前の絵は 329×247px）。札は 150×44px で、題名とうさぎにかからない |
| 誰でも | ○ | 札のコントラスト比は 5.29 対 1。ボタンの名前は「この飲ませ方を動画で見る」 |
| 流れ | △ | 2回目と同じ。0〜1歳には動画が無い |
| 入力 | — | 入れる所は無い |

直したもの: なし。△ は様子見（ユーザーが決める）。縦長が気になるなら、サムネイルを小さくするか、上の絵だけを切り取る。

### 2026-11-13（2回目。やり方の絵を、動画のサムネイル（表紙）にした。絵を押すと動画が出る。手元（localhost）でだけ。幅 390px）

きっかけ: 持ち主（ユーザー）が「動画がどこにあるか分からない」。ユーザーの指示「この絵を、動画の見出し（サムネイル）にしてほしい」。
変えたこと: 動画のあるやり方（1〜3歳と4歳からの6つ）は、開くと出る絵そのものをボタンにして、絵の下に「▶ 動画で見る」の札を重ねた。手順の下にあった文字のボタン「▶ この飲ませ方を動画で見る」は外した（同じことが2つにならないように）。動画のないやり方（0〜1歳の3つ、食べ物に混ぜる）は、今までどおり絵だけ。

| 観点 | 結果 | 見つかったこと |
|---|---|---|
