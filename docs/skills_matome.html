スキルのまとめ

Claude に「この手順でやって」を覚えさせておく仕組みがスキルです。ここでは、このプロジェクトで使えるスキルを、いつ使うかと一緒にまとめました。（2026-10-18）

スキルってなに？

決まった仕事の手順書です。Claude は話の内容を見て、合うスキルがあれば、その手順に沿って作業します。

使い方は2つあります。

  1. ふつうに頼む: 「FB きた」「意見もらった」のように言えば、Claude が合うスキルを選びます
  2. 名前で呼ぶ: /fb-triage のように、/ とスキルの名前を打ちます

スキルは、CLAUDE.md と同じ「ハーネス（AI に正しく作業させるための決まりや仕組み）」の1つです（CLAUDE.md の「最上位の考え」）。うまくいかないときは、手順書を直して育てます。

このプロジェクトのスキル

fb-triage

FB のトリアージ（仕分けと優先度づけ）

こんなとき: メンター、参加者、使ってくれた親から意見をもらったとき。Slack の文を貼って「FB きた」と言えば動きます。

  1. 記録する — docs/18 に1件ずつ書く。原文は貼らず要点に。本名や家族のことは書かない
  2. 仕分ける — 下の4つの区分のどれかに入れる
  3. 優先度をつける — 下の問いに順に答えて、高・中・低を決める
  4. ユーザーが決める — Claude は案と「次の一歩（小さく1つ）」を出すだけ。Slack の返事の下書きも出す（12時間以内に反応する決まり）

区分

区分どんな意見行き先
安全医療上の判断、個人情報、薬の情報の出どころ・許可まず薬剤師（自分）が見る
機能作るもの、直すものdocs/19 の候補、docs/17
考え方進め方、作り方の助言CLAUDE.md
確認意味がはっきりしない相手に聞き返す

優先度の決め方（上から順に）

  1. 安全に関わる？ → はい なら 高
  2. それで子どもが飲むようになる？ → いいえ なら 低（今は作らない）
  3. 入口で止まっている？（薬が検索で見つからない など） → はい なら 高
  4. 小さく作れる？ → いいえ なら、小さく分けた最初の1つだけを候補に
  5. 作り直しが高い？（保存するデータの形、資料の許可、個人情報） → はい なら、作る前に決める
  6. どれでもなければ 中

html-plan

作る前の計画を1ページで

こんなとき: 何かを作る前に「思っていたのと違う」を防ぎたいとき。/html-plan 作りたいもの と打ちます。

  1. 読む — 計画のページ（スマホでも開ける）を読む。たたんだまま一番上だけ読めば、何が変わるか分かる
  2. 決める — 決める欄（1〜3個）を選ぶ。どこにでもコメントできる。全体の意見は一番下の「全体へのひとこと」へ
  3. 返す — Respond → Copy response → チャットに貼る

コミュニティ plugin（2026-10-23 に入れた）。このプロジェクト用の決まり（日本語で書く など）は CLAUDE.md の「進め方のメモ」。くわしくは docs/21。

shinchokuhyou

進捗表（いまどこ？次はだれ？）

こんなとき: 作業が3ステップ以上になるとき。Claude が最初に「進捗表を使いますか」と聞きます。/shinchokuhyou でもすぐ使えます。

  1. 毎回の返事の最後に、全部のステップの表が出る
  2. 印: ✅ 済み、▶ いまここ、⬜ まだ、⏳ 待ち
  3. 台帳は .claude/shinchokuhyou/ に残る（GitHub には上げない）。日がかわっても続きから始められる
shuuhou

週報を作る

こんなとき: 毎週の週報を書くとき。「週報」と言うか、/shuuhou と打ちます。

  1. その週の git のコミットと、Claude と作業した時間帯から、「今週やったこと」の下書きができる。作業時間はチャットで見せるだけで、週報には書かない
  2. 「相談事」と「サマリー」は自分で書く（運営の決まり）。Claude は事実を並べて思い出す手伝いだけ
  3. 「出して」と言うと、名簿リポジトリに PR を出す。Slack で共有する文の下書きも出る

下書きは private/shuuhou/ に残る（GitHub には上げない）。

MulmoTerminal のスキル

MulmoTerminal（たくさんの Claude を並べて動かす道具）を入れると付いてくるスキルです。困ったら、まず help か config に聞けば、合うスキルに案内してくれます。

mulmoterminal-help

使い方を聞く

こんなとき: 「この機能はなに？」「どうやるの？」「新しいバージョンで何が変わった？」

mulmoterminal-config

設定の入口

こんなとき: 「何を変えられる？」「設定が効いていない」「今どう設定されている？」

mulmoterminal-bug-report

こわれた？を調べる

こんなとき: 「動かない」「おかしい」。設定のせいか本当の不具合かを調べてから、報告を作る

mulmoterminal-decisions

前に決めたことを見る

こんなとき: 「これ前に決めたよね」。過去に聞かれたことと答えを読んで、同じ質問をくり返さない

mulmoterminal-dirs

フォルダごとの色と並び

こんなとき: 「このプロジェクトに色をつけたい」「よく使うものを上に」「文字が小さい」

mulmoterminal-header

画面の上のボタン

こんなとき: 「ワンクリックで○○したい」「上にブランチ名や PR を出したい」

mulmoterminal-keys

キーボードのショートカット

こんなとき: 「Enter で改行したい / 送りたい」「コピーがうまくいかない」「待っている Claude にすぐ移りたい」

mulmoterminal-notify

通知の音

こんなとき: 「通知がうるさい / 少ない」「返事待ちのときだけ鳴らしたい」「スマホに通知が来ない」

mulmoterminal-theme

画面の色（テーマ）

こんなとき: 「自分の色の組み合わせを作りたい」「暗すぎる / 見にくい」

mulmoterminal-model

ちがう AI モデルを使う

こんなとき: 「安いモデルを使いたい」「プロジェクトごとにモデルを変えたい」

mulmoterminal-shared-app

みんなで使うものを作る

こんなとき: アンケート、申し込みフォームなど、ほかの人が書きこむものを作って公開する

親へのアンケート（「いくらなら払う？」など）に使えるかもしれません。個人情報を集めない作りにします。

スキルを増やすとき

同じことを2〜3回 Claude に頼んだら、スキルにする合図です。「これをスキルにして」と言えば、手順書を作ります。

このプロジェクトのスキルは .claude/skills/ に置きます（fb-triage は .claude/skills/fb-triage/SKILL.md）。MulmoTerminal のスキルは自分のパソコンの ~/.claude/skills/ にあり、どのプロジェクトでも使えます。
