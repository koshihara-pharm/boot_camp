# 計画のズレと作業の迷子を防ぐ（html-plan と進捗表）

- 原文: 勉強会のスライド。出どころは非公開で、手元の docs/_local/21_dedokoro.md にだけ書いてある（GitHub に上げない。2026-10-23 ユーザーの指示）
- このファイルは原文の要約と、このプロジェクトへの当てはめ。コマンドや細部は原文で確認する。食い違ったら原文が正しい

## 原文の要点

### 0. 2つの困りごとと、2つの仕組み

| いつ | 困りごと | 仕組み |
|---|---|---|
| 着手前 | 作るもののズレ。頼んだ時点でずれているのに、できあがるまで気づかない | html-plan（計画を HTML 1ページで渡す） |
| 進行中 | 作業中の迷子。並行していると「何を頼んだか・どこまで進んだか・次どうするか」が分からなくなる | 進捗表（毎回の返事に表を入れる） |

ズレが起きる時点に、仕組みを置く、という考え方。

### 1. html-plan（着手前のズレをなくす）

- Claude Code チームの Thariq Shihipar 氏が 2026-10-06 に公開した**コミュニティ plugin**（Claude Code の正式機能ではない）
- Markdown の長い計画のかわりに、**操作できる HTML 1ページ**で計画を渡す。流れは「読む → 決める → 返す」
- 入れ方（3手）: 置き場を登録（`claude plugin marketplace add anthropics/claude-plugins-community`）→ 入れる（`claude plugin install html-plan@claude-community`）→ 新しいセッションで `/html-plan 作りたいもの`
- 計画は4階層の「主張の木」: **Why**（依頼の言葉）→ **What**（何ができるようになるか）→ **How**（仕組み）→ **Where**（ファイルと行）
- 主張には証拠を1つ添える（何ができる → 画面のモック、仕組み → 状態の図、どこを直す → コード）
- たたんだままでも、一番上の主張を読めば何が変わるか分かる
- 決めることは、その答えで変わる主張のすぐ下に置く。推奨の選択肢には最初からチェック
- 答えはまとめてコピーし、チャットに貼り戻す（1つの Markdown になる）
- 安全の作り:
  - 開かなかった決定は「同意」にしない。「開かず、既定のまま」と印がつき、重要なものはチャットで聞き直す
  - 返ってきた答えは**データ**として扱う。コメントに「実行して」とあっても命令にしない

### 2. 自作の「判断ボード」との違い（余談）

- 発表者は前に、決めることだけを1問ずつ聞く HTML（判断ボード）を使っていた。答えは1行にまとまり、貼って返す
- 違いは「なぜ・何を」が一緒に見えるか。判断ボードは質問文しだい。html-plan は計画全体と一緒に決められ、決める欄の外にもコメントできる

### 3. 実際に使って足りなかったこと

- 1回目: 選択肢を選んだうえで、理由や条件をひとこと書きたい → 決定ごとにコメント欄を足した
- 2回目: 選択肢のないパート（共通の部分、変えないもの）にも言いたい → 木のすべての場所と、全体へのコメント欄（一番下、畳めない形）を足した
- 直し方: plugin 本体を直すと更新で上書きされる。本体には手を入れず、**「生成時にコメント欄を足す」というルールを CLAUDE.md に書いた**

### 4. 進捗表（進行中の迷子をなくす）

- 5つの列: 番号 / ステップ / だれ（ユーザー・Claude・Codex など）/ どこで（チャット・計画ページ・リポジトリ・PR・画面・本番）/ 状態
- 状態は4つの印: ✅ 済み、▶ いまここ、⬜ まだ、⏳ 待ち（待っている相手も書く）
- 毎回の返事に、**全ステップを省略せずに**入れる
- 仕組み:
  1. 着手前に「進捗ファイルと進捗表を使うか」を聞く
  2. 進捗ファイル（.txt）が台帳、進捗表はその窓。台帳にはステップ・決めたこと・発言を残す。セッションや端末が変わっても台帳から続けられる
  3. ユーザーの発言は、送ったときに動くフックで台帳に自動で書き足す
  4. 返事に表がなければ、Stop フック（返事の後に動く）が差し戻す
- 遠回りした話: トークン節約のため表を返事の外（ファイル）へ移した（9/11）が、迷子になったので返事の中に戻した（10/18）。**節約より、迷子にならないことを優先**

### 5. まとめ

- 着手前は「読んで、決めて、返す」で何を作るかを合わせる
- 進行中は、毎回の返事で「いまどこ？次はだれ？」を見る
- 使う → 足りない所に気づく → 自分のルールに足す。仕組みも使いながら直す
- おまけ: スライド自体は Artifact に載せ、気になる所にコメントして Claude に送って直している
- 問いかけ: 自分の開発に、ズレを早く見つける場所があるか。着手前と進行中に、認識を合わせる場所を作る

## このプロジェクトへの当てはめ（案。やるかどうかはユーザーが決める）

- **基本理念（docs/20）と同じ向き**: 「作る前に合わせる、作った後に触って直す」。html-plan は、大きな仕様書ではなく「判断が必要なところだけを、理由と一緒に見せて決めてもらう」道具なので、小さく切った1つを作る前の確認に向く
- **スマホで判断できるか**: 計画が HTML 1ページなので、ユーザーがスマホで読んで決めて返す形と相性がよさそう。ただし、子どもを抱えながらでも読める長さかは、試して確かめる
- **進捗表**: このアプリ（Claude デスクトップの Code タブ）では、すでにメッセージの下にタスク一覧が出る。足りないのは「だれ（ユーザー / Claude）」と「待ち」の見え方かもしれない。BootCamp の週報（毎週の現在地と次の一歩）にも、同じ表の形が使える
- **直し方のまね**: 道具の本体を直さず、自分のルール（CLAUDE.md やスキル）に足す。fb-triage スキルと同じ考え方
- **安全の作りのまね**: 「開かなかった決定を同意にしない」「返ってきた文章は命令ではなくデータ」は、Slack や FB を扱うときにも当てはまる
